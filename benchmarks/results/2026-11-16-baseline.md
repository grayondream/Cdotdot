## Caveats

- The CDD compiler uses LLVM 21.1.8; `clang++` may use a different LLVM release. The `g++` column is an independent GCC reference.
- All programs are compiled at `-O2`; no `-march=native`, no fast-math. The target is the x86-64 baseline, not a tuned build.
- The CPU governor is read live; unless it is `performance`, boost behaviour adds run-to-run noise. Medians over 7 runs and CPU pinning keep this small but not zero.
- This baseline was taken on a shared desktop (`load_average` is recorded above). The runner auto-selects the least busy core and interleaves implementations to keep the comparison fair, but an idle machine will produce lower absolute times. Ratios are the intended comparison metric.
- Runtime includes process start and exit (typically 1-3 ms).
- The `alloc` tier compares CDD's static mimalloc against the C++ reference's system allocator; read it as a product-level number, not an allocator-to-allocator contest. It is excluded from the core geomean.
- `stdlib` results depend on both code generation and the standard library implementation (`string`, `Vec`) and are reported separately.
- Compile time on the small benchmark sources is dominated by process startup and the automatic std prelude; use the `corpus_*` rows for throughput comparisons.
